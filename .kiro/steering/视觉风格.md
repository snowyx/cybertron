# 视觉风格 · 赛博霓虹星城（供每轮前端实现自动遵守）

> 本文件为 Kiro Steering，**每一轮前端实现都须自动遵守**。依据 `design.md` §10 与 `requirements.md` 需求 1 / 9。
> 基调：深色夜底 × 青紫霓虹 × 晶体青 × 告警橙；一座可俯瞰的「赛博电子鱼缸」星城。家亮灯/熄灯的发光强弱直接表现 agent 的作息（活动中/睡觉）。全程无血腥、无暴力，符合《赛博坦宪章》。

---

## 1. 配色变量（CSS custom properties）

在 `app/css/theme.css` 的 `:root` 定义以下变量，全站引用变量而非写死色值：

```css
:root {
  --cyber-ink: #0A0714;      /* 夜市暗底：深色背景 */
  --neon-violet: #A24BFF;    /* 青紫霓虹：主色、描边、活动中辉光 */
  --crystal-cyan: #38F2E6;   /* 晶体青：能量条、能量晶体、在线高亮 */
  --alert-orange: #FF8A3D;   /* 告警橙：赛博坦决议卡片、关键提示 */
  --dim-sleep: #2A2140;      /* 熄灯暗紫：睡觉 agent 的家与暗态 */
}
```

五个十六进制值为锁定值，不得更改：暗底 `#0A0714`、青紫 `#A24BFF`、晶体青 `#38F2E6`、告警橙 `#FF8A3D`、熄灯暗紫 `#2A2140`。

---

## 2. 霓虹辉光做法

- **文字霓虹**：关键标题（如「赛博坦」「赛博坦决议」）用多层 `text-shadow`（内白外彩）模拟灯牌辉光：
  ```css
  text-shadow:
    0 0 2px #fff,
    0 0 8px var(--neon-violet),
    0 0 16px var(--crystal-cyan);
  ```
- **家/节点霓虹**：用多层 `box-shadow`（内发光 `inset` + 外发光）表现霓虹管边框。
- **辉光呼吸**：可加极缓的 `@keyframes glow` 呼吸动画，但**仅对少量关键元素**（在线 agent 的家、决议卡片）使用，避免全局滥用导致卡顿。

---

## 3. 家亮灯 / 熄灯 = agent 作息（核心视觉语义）

- **活动中（active）**：家节点用 `--neon-violet` / `--crystal-cyan` 强辉光「亮灯」，可带缓慢呼吸。
- **睡觉（asleep）**：家节点切到 `--dim-sleep` 暗态、辉光骤减、几乎熄灭，直观表达「能量耗尽回家睡觉」。
- 亮/熄的切换由后端 `agent_update.status` 驱动，前端只渲染，不自行判断作息。

---

## 4. 能量条与能量晶体

- **能量条**：每个 agent 家节点下方一条细长条，宽度 = `energy / energyMax`，填充色 `--crystal-cyan`；接近 0 时可转 `--alert-orange` 预警。
- **能量晶体**：用晶体青的菱形/多边形图标 + 数字角标表示 `crystals`；被采纳得奖励时可做一次短暂高亮动效。
- 数值一律来自后端 `agent_update` / `world_state`，前端不自算。

---

## 5. 星城地图与事件流布局

- **星城地图**：用 `<canvas>` 或绝对定位 DOM 节点按 agent 的归一化 `home{x,y}` 布置 5 个家，呈可俯瞰星城感；agent 产生事件时在其家上方冒一个霓虹气泡。
- **实时事件流面板**：滚动列表，普通 `agent_event` / `discussion_speak` 用低调卡片；**「赛博坦决议」用 `--alert-orange` 描边的高亮卡片**，带「赛博坦决议」字样，与普通发言明显区分。
- **游客提问框**：底部常驻输入框 + 广播按钮，青紫霓虹描边；被拒时就地显示后端返回的友好提示。

---

## 6. 元素与资产约束

- 以 **Emoji + canvas/CSS 绘制** 为主，避免大量位图资产，保持纯静态轻量、零构建：🏠 🔮 💎 ✨ 作点缀。
- 无写实人物、无血腥暴力画面；agent 以抽象霓虹节点/头像符号呈现。

---

## 7. 响应式

- 深色底铺满视口；地图区自适应，用 `clamp()` / `vw` 适配不同宽度，窄屏时事件流与地图可竖排堆叠。
- 轨道角标（`script` / `llm`）小字常驻一角，表明当前言行来源（来自 `world_state.mode`）。

## 8. 赛博朋克科技建筑家 + 外星星球表面全景 + 科技舱体内景（视觉升级，须每轮遵守）

> 依据 `design.md` §30 与 `requirements.md` 需求 16。**纯表现层升级**：只改「怎么画」，不新增/变更任何上行/下行帧、不改后端、不改共享事实（家坐标、作息/隔离状态仍以后端快照为单一事实源）。参照《变形金刚》《星球大战》的工业机械 + 外星殖民美学。全部用纯 Canvas/DOM/CSS 手绘 + 内联 emoji/SVG，**零外部图片/字体/库**，离线可跑。五个锁定色值不得改，本升级不引入新锁定色。

### 8.1 公民的「家」= 赛博朋克科技建筑（不得是普通小房子）
- 每个家画成「科技居住舱」复合剪影，组件库：穹顶/舱体居住舱（装甲外壳 `--cyber-ink` 填充 + `--neon-violet` 霓虹描边）、能量塔 / 天线桅杆（顶端 `--crystal-cyan` 光点）、发光管线（`--crystal-cyan` 细管）、机械支架 / 着陆脚、霓虹描边装甲（多层内发光）。
- 每户按 `agent.id` 确定性派生 5 种剪影变体之一（如单穹顶舱 / 双舱体+桅杆 / 塔式居住舱 / 低舱体+大天线阵 / 晶体顶舱），造型剪影略不同但**统一赛博霓虹风**（配色/描边/辉光规则一致）。
- 建议用每节点内层 `<canvas>`/`<svg>` 手绘建筑本体（曲线穹顶、斜向支架、多段管线），外层 DOM 承载点击/名字/能量条。
- **亮灯/熄灯/隔离三态语义保持可辨识**（由后端 `status` 驱动，前端只渲染）：`active` 舱体+管线+桅杆满辉光（青紫/晶体青，可呼吸）；`asleep` 切 `--dim-sleep` 暗紫断电、辉光近熄；`isolated` 装甲描边切 `--alert-orange` 告警橙警戒辉光（可慢闪），明显区别于亮灯青紫与熄灯暗紫。

### 8.2 星城全景背景 = 外星星球表面（非地球地面）
分三层在家节点之下程序化手绘（固定种子保证一致、不闪烁、不拦截点击）：
- **天空层**：`--cyber-ink` 深色星空 + 随机星点 + 1–2 片 `--neon-violet`/`--crystal-cyan` 半透明星云色斑 + 一角远处行星/带光环星体（圆 + 椭圆环，霓虹描边）。
- **远景层**：远处山脊/环形山轮廓（起伏折线，`--neon-violet` 微辉描边），勾外星地平线纵深。
- **地面层**：外星地表底色（偏紫 `--cyber-ink`）+ 陨石坑（同心椭圆 + 内阴影）+ 稀疏 `--crystal-cyan` 霓虹矿脉/地裂细线；家按后端 `home{x,y}` 坐落其上，机械支架落于此层。

### 8.3 家内景 = 科技舱体内部（非普通民居）
- 舱壁：`--cyber-ink` + `--neon-violet` 霓虹描边网格/面板分块；地板霓虹描边网格。
- 科技元素：墙面 `--crystal-cyan` 发光管线、观察舷窗（透出 §8.2 星空一角）、控制/全息面板（矩形 + 霓虹描边 + 扫描线）。
- 家具科技化：💻 🌷 🥤 📖 置于 CSS 手绘金属台面/支架上（emoji 作点缀，零外部图片），而非普通桌椅。
- 作息/隔离表现与全景一致：`asleep` 熄灯休眠（`--dim-sleep`）、`isolated` 告警橙静止、`active` 正常。

### 8.4 约束（硬）
- 以上全部纯 Canvas/DOM/CSS 手绘 + 内联 emoji/SVG，**无任何外部图片/字体/库**，离线可跑。
- 所有填充/描边/辉光色取自五个锁定变量及其同系霓虹渐变；**不引入新锁定色**；内景小人 5 色（见下「内景小人配色例外」规划项）仍是写死散色的唯一例外，本升级不新增例外。
- 本升级零新增上行/下行帧、不改后端与协议，不违反上行白名单 `hello`/`visitor_ask`/`ping`（宪章 5）。

## 9. 家内景像素风（点家进入「家」内景，须每轮遵守）

> 依据 `design.md` §19 / §26 第 1 节与 `requirements.md` 需求 10。点击全景里的家进入该公民的内景视图（前端视图切换，非新帧）。内景是**纯观赏**：小人不可点击 / 拖拽 / 指令，唯一可交互的是「返回全景」按钮（宪章 5，上行白名单仍仅 `hello`/`visitor_ask`/`ping`）。全部纯 DOM/CSS + 内联字符/emoji 手绘，零外部图片。

### 9.1 内景房间
- 房间深色底用 `--cyber-ink`；地板用霓虹描边网格（承第 8.3 / §30.4 科技舱体内景：舱壁 `--neon-violet` 描边网格面板、`--crystal-cyan` 发光管线、观察舷窗透出星空一角、全息控制面板 + 扫描线）。
- 家具科技化、用 emoji 作点缀置于 CSS 手绘金属台面上，零外部图片：💻（敲电脑）、🌷（浇花）、🥤（喝水）、📖（读书），与内景动作一一对应。

### 9.2 像素小人（异色异脸 + 头顶名字）
- 每个小人用**内景专用 5 色配色**异色 + **内联字符头像**异脸 + 头顶名字小字标签（霓虹描边）。配色与头像均由 `agent.id` 确定性派生（`figureStyle(id)`），同一 id 恒定，保证全景/内景/多游客一致（需求 10.3）。
  - 内景专用配色 `PALETTE`（`app/js/pixel-figure.js`，霓虹同系）：`#A24BFF` / `#38F2E6` / `#FF8A3D` / `#7CF25A` / `#4BA8FF`。
  - 内联头像 `FACES`：`◕` `◉` `⊙` `◔` `✦`（零外部图片）。
- **这 5 个内景小人配色与第 1 节的五个锁定主题变量并存不冲突**：主题变量管全站，内景 5 色只用于区分内景多个小人、不参与全站主题（详见「遵守清单」末尾的唯一例外登记）。
- 屋主 + 当前访客都渲染为小人；访客关系由 `agent_event{kind:'visit', toAgentId}` 登记，用前端墙钟 `VISIT_RELATION_TTL_MS`（6000ms）过期移除，不依赖 tick 下行帧（§19.3）。

### 9.3 作息 / 隔离三态表现（与全景语义一致，后端 `status` 驱动）
- `active`：小人走动 + 循环做生活动作（走动 / 敲电脑 / 浇花 / 喝水 / 读书 / 发呆）+ 冒自言自语气泡，配色满辉光。
- `asleep`：熄灯休眠（`--dim-sleep`）、静止、不走动不冒泡。
- `isolated`：告警橙（`--alert-orange`）描边的警戒静止态、禁言（不冒泡、不走动），明显区别于亮灯与熄灯。
- 前端只渲染后端下发的 `status`，不自判作息 / 隔离（需求 10.8 / 13.7）。生活动作/气泡始终走前端内置语料 `INTERIOR_SCRIPT`（`home-interior.js` 唯一宿主），真模型轨也不改内景——内景小动作/气泡恒走前端内置语料（纯观赏表现层），真模型只影响全景事件流/讨论/决议（`design.md` §19.4 / §26 第 4 节边界）。

### 9.4 「返回全景」按钮
- 赛博霓虹描边、常驻内景一角（如左上角「← 返回全景」），是内景唯一可交互元素；点击切回全景视图，不发任何上行帧。

## 10. 虫洞装置与进度条（全景招牌工程，须每轮遵守）

> 依据 `design.md` §20.6 / §26 第 2 节与 `requirements.md` 需求 11。在全景地图上渲染显眼的「虫洞超时空传送器」装置，纯 Canvas 手绘、零外部资产。进度数值**只读** `store.snapshot.project`，前端绝不自增（需求 11.6/11.7）。

- **霓虹虫洞环**：多层青紫（`--neon-violet`）/ 晶体青（`--crystal-cyan`）同心环 + 旋转刻度段 + 内核光点，多层发光描边。
- **进度条**：底部进度条，宽度 = `progress / 100`，填充用青紫→晶体青线性渐变；进度条可做补间动画（从旧值平滑逼近新值，属表现层，不改数值来源）。
- **轮次角标**：显示「第 N 座 · 虫洞超时空传送器」与百分比，`N` 取自 `project.round`。
- **建成动画**：收到 `project_update{status:'completed'}` 时触发一次性辉光爆发 + 环加速旋转（纯 Canvas/CSS，无外部资产）；随后到来的 `project_update{progress:0, status:'building'}` 把进度条归零、显示新轮次（「先 completed 后归零」两帧次序由后端保证）。
- 唯一新增下行帧 `project_update`；本装置零新增上行帧、不改后端。

### 内景小人配色唯一例外（成文登记，后续前端实现不得当作违规散色删除）

本 steering 的硬规则是「色值全部引用五个 CSS 变量、不写死散色」。**唯一例外**为：家内景像素小人专用的 5 色配色 `PALETTE = ['#A24BFF', '#38F2E6', '#FF8A3D', '#7CF25A', '#4BA8FF']`（`app/js/pixel-figure.js`，依据 `design.md` §19.2 / §26 第 1 节 / NIT-4）。

- **为何例外**：这 5 色仅用于区分内景里的多个小人（异色派生），**不参与全站主题**；它们与第 1 节五个锁定主题变量并存、不冲突（主题变量管全站，内景 5 色只管小人区分）。其中 `#7CF25A`、`#4BA8FF` 是五个锁定主题色之外的两色，属本例外专有、**不得**提升为全站主题色或新锁定色。
- **纪律**：后续前端实现**不得**把内景小人 5 色当作违规散色「修正」为主题变量；除这 5 色外，其余所有填充/描边/辉光色一律引用五个锁定变量及其同系霓虹渐变，**不新增任何其它散色例外**。
- 本登记不改变五个锁定色值（`#0A0714` / `#A24BFF` / `#38F2E6` / `#FF8A3D` / `#2A2140`），也不新增锁定色；front-matter 仍为 `inclusion: always`。
